# 实验过程落库规范

本规范适用于 E1–E5 的每一次 run。模板中的空栏位是待填项，不是示例结果。没有跑过的实验不要写指标。

## 一次 run 的三个时点

### 1. 开跑前登记

在 `experiments/<线>/runs/YYYY-MM-DD-<短名>.md` 建档，至少写完：

- 日期、负责人、状态（`登记`）
- 场景：名称、来源、使用的划分或序列
- 数据授权：许可证、内部批准或「公开数据、可再分发」一类说明。写不清授权就不要开跑
- GPU：型号、数量、显存
- 被测代码：仓库 URL 与完整 git commit
- 假设：这次要验证的一句话，以及 Go 所依赖的判据

文件名里的日期用开跑日。短名用小写英文或拼音，词之间用连字符，例如 `2026-11-04-replica-room0.md`。

### 2. 开跑回报

状态改为 `进行中`。若与登记时不同，改写并留一句原因：

- 实际场景
- 实际 GPU
- 实际使用的数据授权范围

回报写在同一个 run 文件里，不另开聊天备忘。

### 3. 结束后

状态改为 `已结论`。在同一文件内完成下面四块，合起来应当能在一页内读完；步骤细节可以更长，结论本身保持一页。

- **结论**：回答假设。写观察到的事实，不把未测的项说成已测。
- **指标表**：每一行包含指标名、操作定义、数值、对照（同一次对比中的另一配置，或写「无」）、备注。没有数值就留空，不要填 0 来占位。
- **Go / No-Go**：`Go`、`No-Go` 或 `未判定`。未跑完必填项时用 `未判定`。
- **日志路径与失败模式**：日志可在仓库外。失败时写现象、当时的判断、是否阻塞这条实验线。

## 仓库里允许的内容

允许：

- Markdown
- 小图（png / jpg / webp / svg）。单张尽量小于 1 MB，用相对路径引用
- 指向外部存储的 URL（对象存储、数据集页面、权重发布页、日志平台）

不允许直接提交：

- 高斯（`.ply`、压缩 splat）、检查点、ONNX、网格、点云、视频、压缩包、数据集目录
- 训练框架的默认输出目录（如 `outputs/`、`wandb/`、`logs/`）

这些后缀已列在仓库根目录的 `.gitignore` 中。若某份产物必须进版本库，二选一：

1. **Git LFS**（二进制需要跟本仓库一起版本化时）

   ```bash
   git lfs install
   git lfs track "<要跟踪的模式>"
   git add .gitattributes
   ```

   先在 run 文件里说明为什么不能外链，再跟踪具体模式。不要为了省事跟踪整个目录。

2. **外链**（默认选择）

   在「日志路径」写可访问的 URL，并注明保留期限和谁有权读取。链接失效时补新地址，不要把文件补进 Git 历史。

本仓库的提交只记录文字和小图。被测代码的改动留在对应代码仓库，并用 commit 号指回这里。

## 状态

| 状态 | 含义 |
| --- | --- |
| `登记` | 已建档，尚未开跑 |
| `进行中` | 已开跑，结论未写 |
| `已结论` | 已有结论、指标表和 Go/No-Go |
| `放弃` | 开跑后中止。保留已写步骤和失败模式，不删除文件 |

已结论的数字不改写。发现记错时，在文末加「更正」：日期、错在哪里、正确值、依据。更正不改变原表，只追加说明。
